The `/demo` keeps a machine in lockstep across every open tab: one **leader** tab
owns writes, and the others receive updates. The pieces are already in place —
[`useActorSync`](/effstate/guides/persistence/#useactorsync) for the two-way flow,
`localStorage` for the shared channel, and the browser `storage` event for
change notification.

## The pattern

1. Elect one leader tab.
2. The leader serializes each snapshot and saves it to `localStorage`.
3. Every other tab hears the `storage` event, reads the new value, and applies it
   to its own actor via `_syncSnapshot`.

## Leader election

Any single-writer scheme works. A minimal one: claim a flag in `localStorage` and
treat yourself as leader only if the flag holds your id.

```ts
const TAB_ID = crypto.randomUUID();
const LEADER_KEY = "stopwatch:leader";

function isLeader(): boolean {
  const current = localStorage.getItem(LEADER_KEY);
  if (current === null) {
    localStorage.setItem(LEADER_KEY, TAB_ID); // claim it
    return true;
  }
  return current === TAB_ID;
}
```

<Aside type="note">
For production you'd add a heartbeat/expiry so a closed leader releases the flag,
or use the Web Locks / `BroadcastChannel` APIs. The mechanism is orthogonal to
effstate — all `useActorSync` needs is a boolean.
</Aside>

## Wiring it up

The leader writes; a `storage` listener feeds the changed value into follower
state, which `useActorSync` applies:

```tsx
import { useEffect, useState } from "react";
import { useActor, useActorSync } from "@handfish/effstate-react";
import { Union, Schema } from "@handfish/effstate-v4";
import { Idle, Running, stopwatch } from "./stopwatch";

const SnapshotSchema = Schema.Struct({
  state: Union(Idle, Running),
  context: Schema.Struct({ elapsed: Schema.Number }),
});
const KEY = "stopwatch:snapshot";

function SyncedStopwatch() {
  const { actor, context } = useActor(stopwatch);
  const [leader] = useState(isLeader);
  const [external, setExternal] = useState<string | null>(null);

  // Followers: mirror storage changes into local state
  useEffect(() => {
    if (leader) return;
    const onStorage = (e: StorageEvent) => {
      if (e.key === KEY && e.newValue) setExternal(e.newValue);
    };
    window.addEventListener("storage", onStorage);
    return () => window.removeEventListener("storage", onStorage);
  }, [leader]);

  useActorSync(actor, external, {
    isLeader: leader,
    serialize: (snap) =>
      JSON.stringify(Schema.encodeSync(SnapshotSchema)(snap)),
    deserialize: (saved: string) =>
      Schema.decodeSync(SnapshotSchema)(JSON.parse(saved)),
    onSave: (json) => localStorage.setItem(KEY, json),
  });

  return <h1>{context.elapsed}s</h1>;
}
```

The leader's `onSave` fires the `storage` event in other tabs; each follower's
listener sets `external`, and `useActorSync` calls
`actor._syncSnapshot(deserialize(external))`.

## Why _syncSnapshot, not send

`_syncSnapshot` sets a snapshot from an external source. When the incoming state
**tag** differs from the current one, it runs the corresponding `exit` and
`entry` effects — so followers stay behaviorally consistent with the leader
(logging, timers started in `entry`, and so on), not just visually. Run streams
tied to a state start and stop as the tag changes, exactly as if the transition
happened locally.

## Multiple actors

For apps with several machines, sync each actor independently, then use
[`useActorBridge`](/effstate/guides/react/#useactorbridge) to wire cross-actor
effects — for example, letting one machine's context drive another:

```tsx
useActorBridge(
  power.actor,
  door.actor,
  (snap) => snap.context.electricityLevel > 0,
  (isPowered) => (isPowered ? Unlock.make() : Lock.make()),
);
```

Each actor persists and syncs on its own channel; the bridges re-derive the
cross-actor relationships in every tab. This is exactly how the `/demo` works.
